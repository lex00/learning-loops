Study Notes for Language Universe

Four pieces of prior art read closely for what they draw, how they move, how they were built, and what carries into a proof of concept of the marble run.

Aquascope

The Rust Book, experimental edition · playground · source · Crichton, Gray, Krishnamurthi, OOPSLA 2023

What it draws

Every path in the code carries three permissions, drawn as the letters R, W, and O for read, write, and own. A statement that changes them is annotated with only the change: +R+W+O when a binding is created, a minus when a borrow takes one away, and a small icon for the cause. The paper is explicit that they draw differences rather than full state because it "helps readers better see how operations affect permissions."

The one visual signal for a program that will not compile is a hollow letter placed between an operator and its operand: the permission that was expected there and is missing. There is no separate error panel. The violation sits on the spot where it happens.

A second view interprets the program and draws stack frames beside a heap, with pointers as literal arrows. Time is unrolled into several side-by-side snapshots rather than one snapshot you scrub. Moved-out values are greyed, and a double free is annotated in red at the exact instruction.

Why

Their concept inventory found that learners could usually say why the borrow checker rejected a program but could not say what memory bug would occur if it ran, and often fixed lifetime errors by pasting whatever the compiler suggested. The visualization was designed to close that gap. Permissions were chosen over arrows between variables because arrows show what points at what, not why an operation is or is not allowed here. The diagram is a rendering of the compiler's own abstract state, not a metaphor laid on top.

Unrolling lets a person more easily compare changes between states, and it allows a person to see all the information in the diagram without interaction.

A live A/B test against the unillustrated chapter moved quiz scores from 48 to 57 percent across 342 readers.

How it is built

React and CodeMirror 6 for the code panel, with a forked leader-line library drawing arrows between DOM elements, so the rendering is DOM and SVG rather than canvas. A rustc plugin working on MIR produces the permission facts and Miri produces the runtime trace. Diagrams are precomputed at book build time by an mdbook preprocessor and embedded as data. Only the playground computes on demand. The visual layer knows nothing about Rust; only the analysis does.

Take for the marble run. The hollow letter is the gate. A variant that cannot do the thing should show the missing capability at the exact track position where it would be needed, in the same visual language as the capabilities that are present. And their argument for unrolled frames is an argument for a loop made of held beats, so that any frame caught mid-cycle still reads.

samwho.dev

site · source · Sam Rose

What it draws

A small cast of shapes reused across essays: filled circles for requests, hollow circles for timed-out ones, striped circles for priority items, and a queue glyph. The same tiny SVG icon appears inline in the prose next to the word it stands for, so "priority request" is always followed by its shape. The reader learns the vocabulary by pattern matching and then reads the animation without labels.

Colours come from the Wong and Tol colourblind-safe palettes, hardcoded once per project, with contrasting variants derived at runtime against a target contrast ratio. Three cartoon huskies of different ages act as commentators in speech bubbles.

Someone gave me the advice to use animals, ideally animals of very different sizes or colours. People instantly picture them and remember them.

How it moves

Not everything is ambient. Queueing and load balancing keep running while you read; hashing and Bloom filters wait for a click. Anything that runs continuously is wired to an intersection observer and the page visibility event, so it stops offscreen and restarts when it returns. Speed is reader-adjustable through a global time scale. Randomness appears only where it is the concept being taught, such as probabilistic drops, never as texture.

Controls sit directly under the visual they affect and appear only when the essay reaches the concept that needs them. Questions are Socratic, posed in the prose or by a dog, and answered afterward.

How it is built

Plain TypeScript web components, one standalone package per essay, dropped into static HTML with a script tag. Earlier essays render on PixiJS canvas with GSAP tweens and matter-js physics. Later ones dropped both for SVG and the native Web Animations API. Simulation state lives in plain classes under a core directory, fully separate from the rendering classes. Reduced motion is handled by stripping only the scale tweens rather than disabling animation.

Take for the marble run. Put the shape next to the word everywhere the word appears, including any prose around the scene. Keep the simulation as a plain state machine with no knowledge of rendering. Pause offscreen from day one. And let jitter exist only where timing variance is part of the lesson.

RustViz

playground · source · Almeida, Cheng, Kim, Zhao, Omar, VL/HCC 2022

What it draws

A vertical column per variable beside the code, so time runs down the page. A filled dot marks a binding taking ownership. An arrow between columns marks a move or copy. The line for a binding is solid while it is mutable and usable, hollow while it is immutable or while a live borrow forbids mutation, and solid again when the borrow ends. A curved branch off a column shows access through a reference. Conditionals split the timeline, with the inactive branch greyed.

Hovering any mark underlines the matching source line and pops a plain-English message such as "Move from s to takes_ownership()."

What the study found

Across four semesters and 303 students, 93 percent rated the diagrams helpful. The repeated complaint was legibility at a glance rather than the concept. The paper reports feedback like "I still don't know what the double line vs the single line means" and lists a static legend as unresolved future work. Hover text alone did not teach the notation.

How it is built

Two eras under one visual grammar. The studied version is annotation-based: instructors write events in a comment DSL, and a column spec chooses which variables get columns, so irrelevant bindings can be left out. The current rewrite plugs into rustc and derives the same diagram from the real borrow checker. Both emit SVG.

Take for the marble run. Encode the state that must be obvious without attention in stroke or shape, not colour alone. Keep a permanent legend on screen. Let the author choose which marbles are in the scene rather than rendering the full execution. And freeze the visual grammar early, since it survived a total swap of the analysis underneath.

Await Simulator

page · DevOps Daily, one of about fifty-five browser tools in the same house style

What it draws

Four scenarios, each a scripted trace: microtasks beat timers, await suspends the function, rejections jump to catch, and Promise combinators. Six cards share the screen: source with the executing line highlighted, call stack, runtime APIs, a promise inspector, the microtask queue, and the task queue, plus a console.

Everything is neutral grey. A single accent colour marks whatever is happening right now: the executing line, the panel receiving an item, its icon. There is no fixed colour per queue type. Colour means "now," not "this kind of thing."

The predict moment

At scripted forks the run halts and a card asks a plain question such as "What gets printed first after Start?" with a short stack of answer buttons. It is placed where the step counter sits, so it reads as a fork in the road rather than a quiz beside it. What happens on a wrong guess could not be verified because the page is client-rendered.

How it is built

Next.js on Cloudflare Pages. The page states that it does not execute arbitrary JavaScript and that each scenario is modelled as a deterministic event-loop trace. Playback offers step back, play, step forward, reset, and three speeds bound to delays of 1500, 1100, and 650 milliseconds, with slow selected by default.

Take for the marble run. Hand-authored traces are the norm, even in a tool about a real runtime. One accent for "now" fits the lit-path idea. The predict card belongs at a switch, phrased as a prediction about which path the marble takes.

What carries into the proof of concept

  1. Script the run. Every scene is a hand-authored trace of beats, not an interpreter. All four pieces do this or precompute the equivalent.
  2. Ground the track in the runtime's real states. The sections should be the states the scheduler actually uses, so the scene is diagnostic rather than decorative.
  3. A loop of held beats, not fluid motion. Each beat is legible on its own, with a pause, so a frame caught mid-cycle still reads. This is Aquascope's unrolling argument applied to a loop.
  4. Mark the delta at each beat. Show what a marble gained or lost, with a consistent icon for gain and loss.
  5. Put the missing capability where it would be used. The gate is a hollow mark on the track at the switch, drawn in the same grammar as the capabilities that are present.
  6. One accent means now. The lit path and the active marble take the accent. Persistent state is encoded in stroke and shape, solid versus hollow, so it survives colourblindness and a monochrome glance.
  7. Keep a permanent legend on screen. Tooltips did not teach RustViz's notation to 303 students.
  8. Fuse word and shape everywhere. The vocabulary word appears at the moment it fires, and its shape follows the word wherever it is written.
  9. Predict at the switch. Occasionally halt at a branch and ask which path the marble takes in the selected variant.
  10. Let the author suppress marbles. A scene shows the units of work that matter to the concept, not the literal full execution.
  11. Freeze the visual grammar before the data pipeline. Track shapes, switch icons, and the gate are the stable contract. What computes the trace can change later.
  12. Design each scene from a named misconception. Aquascope mined real learner failures first. For the base scene the candidate is "a Python thread runs at the same time as another."
  13. Pause offscreen, expose a speed control, and handle reduced motion by removing only the tweens that cause discomfort.
  14. Separate the state machine from the renderer from the first line of code.

One tension to hold. Aquascope argues against continuous animation and samwho.dev triggers most of its simulations by click, while the concept wants something that runs unattended. The reconciliation is the beat loop in point three: it runs on its own, but each beat is a still picture that holds long enough to read.
